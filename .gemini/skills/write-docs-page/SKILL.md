# Write a sdeway.com docs page

This site is **Astro 7 + Starlight**. Docs live in `src/content/docs/`. The live syntax reference is `src/content/docs/guides/example.md` (on the web: `/guides/example/`). Match that page. Do not invent markdown syntax.

Before writing, read `guides/example.md` and one nearby page in the same folder. The Kroki type catalog is `references/diagrams.md` next to this skill.

## File and URL

Create `src/content/docs/<section>/<slug>.md`.

Existing sections: `guides`, `coding`, `high-level-design`, `low-level-design`, `connect`, `reference`.

Sidebar: `guides`, `coding`, `high-level-design`, `low-level-design` (under "Learnings") and `connect` are autogenerated. `reference` is **not** in the sidebar (template stub). Subfolders are picked up automatically, no config change needed. Some legacy paths contain uppercase (e.g. `coding/Competitive`); leave them alone and never copy that style.

Rules:

- **Entire path lowercase**: folders and filename (`my-note.md`, not `My-Note.md`).
- Use hyphens in slugs. Optional numeric prefixes for ordered series: `00-overview.md`.
- Extension `.md` (or `.mdx` only if the page needs MDX).
- Public URL **drops `.md`** and uses a trailing slash: `src/content/docs/coding/linux/text-editors.md` → `/coding/linux/text-editors/`.
- Internal links must use that URL form, never the source filename: `[Text editors](/coding/linux/text-editors/)`.
- Do not add pages outside `src/content/docs/`.
- A **new top-level folder** also needs a sidebar entry in `astro.config.mjs`: `items: [{ autogenerate: { directory: "…" } }]`.

Frontmatter (YAML). `title` is required; `description` is recommended:

```md
---
title: Page title
description: One-line summary.
---
```

Optional sidebar controls:

```md
---
title: System design
sidebar:
  order: 1
  label: Custom label
---
```

Other frontmatter that exists in the repo: `lastUpdated: YYYY-MM-DD` (override; otherwise git date is used via the `LastUpdated` component). The schema is extended with `starlight-site-graph` fields; don't add unknown keys. Ordered chapter series use `sidebar.order` (see `high-level-design/chapters/`).

Do not use `template: splash` except on the homepage. Start the body with a short intro paragraph (not a duplicate `#` of the title — Starlight already renders `title`).

## Markdown

- Headings: `##` / `###` (page title comes from frontmatter).
- **bold**, _italic_, ~~strikethrough~~.
- Lists, quotes, and normal GFM tables are fine.
- Math (KaTeX): inline `$E=mc^2$`, block `$$ ... $$`.
- Images: standard markdown `![alt](…)` (image zoom is enabled). Static assets go in `public/` and are referenced by absolute path (`/folder/img.png`).
- GitHub profile links `https://github.com/<user>` become avatar badges automatically. Repo URLs stay normal links.
- Do **not** enable raw HTML. Do **not** use an `html` fence to render markup.

## Asides (callouts)

Starlight:

```md
:::tip
Tip body.
:::

:::note[Named note]
Custom title.
:::

:::caution
Caution body.
:::
```

Site-specific (`starlight-markdown-blocks`):

```md
:::success
Advantages (`:::success`).
:::

:::warn
Disadvantages (`:::warn`).
:::

:::info
Info (`:::info`).
:::
```

## HTML diagrams (`renderhtml`) with popovers

Use for UI mockups, waterfalls, timelines, flows, and anything where ASCII art would be hard to read. Prefer this over ASCII/plain-text boxes in docs.

Rules for the fence content:
- Raw HTML/SVG, **no blank lines inside** the fence (a blank line can break parsing). Inline `style=""` only; no `<script>`.
- **Dark mode:** use the theme tokens below for every neutral colour (text, borders, panels, chips). When a fence contains `var(--d-`, the plate automatically follows the site theme (white in light, `#18181b` in dark); fences without tokens keep the old always-light plate (then use fixed light colours and set text colour explicitly).
- Brand/status colours (blue, green, red, ...) stay as fixed hex; they read fine on both plates. Tints: `color-mix(in srgb,#43a047 12%,transparent)`.

| Token | Light | Dark | Use for |
|-------|-------|------|---------|
| `var(--d-fg)` | `#18181b` | `#e4e4e7` | text |
| `var(--d-muted)` | `#6b6b76` | `#a1a1aa` | secondary text |
| `var(--d-border)` | `#d4d4d8` | `#3f3f46` | hairlines, grid lines |
| `var(--d-border-strong)` | `#a1a1aa` | `#52525b` | box outlines |
| `var(--d-surface)` | `#ececf0` | `#27272a` | panel/header fills |
| `var(--d-chip)` | `#d4d4d8` | `#3f3f46` | buttons/chips |
| `var(--d-bg)` | `#fff` | `#18181b` | plate background |

- Set `color:var(--d-fg)` on the root element and never hard-code `#fff`/`#000` text or backgrounds (pastel fills like `#dae8fc` need explicit dark text, so avoid them in themed diagrams).
- Use `min-width` + the wrapper's own overflow so wide diagrams scroll sideways on mobile; use `%` / `position:absolute` for time axes, `display:flex/grid` for layouts.
- Palette used so far: blue `#1e88e5`, green `#43a047`, red `#e53935`, orange `#fb8c00`, purple `#8e24aa`, teal `#26a69a`, greys `#bdbdbd` `#757575`; tint fills with `color-mix(in srgb,#43a047 12%,transparent)`.
- Add a `title="..."` on bars for native hover tooltips.

### Popovers (click + Prev/Next tour)

Any element inside a `renderhtml` block can explain itself. The site script (`src/scripts/diagram-popovers.ts`, styles at the end of `src/styles/custom.css`) adds an automatic **Prev / Next** bar on top of the diagram, a popover on click, arrow-key navigation, hover outline, and keyboard focus.

```renderhtml
<div style="display:flex;gap:.75rem;align-items:center;font-size:.85rem;color:var(--d-fg);">
  <div data-pop-title="Client" data-pop="The browser sends the request. Use `code` in backticks." style="padding:.6rem 1rem;border:2px solid #1e88e5;border-radius:8px;background:color-mix(in srgb,#1e88e5 14%,transparent);">Client</div>
  <span>→</span>
  <div data-pop-title="API" data-pop="Validates the token, then queries the database." style="padding:.6rem 1rem;border:2px solid #43a047;border-radius:8px;background:color-mix(in srgb,#43a047 14%,transparent);">API</div>
  <span>→</span>
  <div data-pop-title="Cache bar" data-pop-tour="0" data-pop="Clickable, but skipped by Prev/Next." style="padding:.6rem 1rem;border:2px solid #fb8c00;border-radius:8px;background:color-mix(in srgb,#fb8c00 14%,transparent);">Cache</div>
</div>
```

| Attribute | Meaning |
|-----------|---------|
| `data-pop-title` | Popover heading |
| `data-pop` | Popover body; plain text, backticks become inline `code`; keep to 1-3 sentences |
| `data-pop-tour="0"` | Still clickable but excluded from Prev/Next (use for many small repeated pieces such as waterfall bar segments) |

Guidelines:
- **Take the explanation text from the surrounding doc** (tables, "what it means" sections) so the popover and prose agree; do not invent facts.
- Put pops on containers (toolbar, table, pane) **and** their children; DOM order is the tour order, so parent comes before children. Click targets resolve to the innermost `data-pop`.
- Tour length: aim for 5-15 items per diagram; mark the rest `data-pop-tour="0"`.
- Escape quotes inside attribute values (`&quot;`) or use single quotes in the text. Do not put `"` unescaped in `data-pop`.
- Many repetitive elements (rows/bars/steps): generate the HTML with a small script (Python or JS) and paste the result, rather than hand-writing it. Python 3.12+ is required if you use nested quotes in f-strings.
- After editing run `bun run build` and open the page: confirm the bar shows, items outline on hover, popover opens beside the item, `←`/`→`/`Esc` work, and both light and dark themes are readable (toggle the theme).

## Tabbed markdown (`group-container`)

For **any** markdown (tables, lists, prose), not just code. **Outer fences use more colons than inner ones.**

```md
:::::group-container

::::group-item[Alpha]{active}

Alpha tab body.

::::

::::group-item[Beta]

Beta tab body.

::::

:::::
```

`{active}` marks the default tab (first item if omitted). Real usage: `src/content/docs/guides/company-apply.md`.

## Interactive tables (`data-table`)

Wrap a GFM table:

```md
:::data-table

| Company | Category |
|---------|----------|
| [Acme](https://example.com) | Product |

:::
```

Attributes: `:::data-table{perPage=50}` · `searchable=false` · `sortable=false` · `paging=false`. Default `perPage` is 25.

Inside content tabs, keep enough colons (`:::::group-container` → `::::group-item` → `:::data-table`).

## Code (Expressive Code)

Meta goes on the opening fence after the language.

Tabbed **code** (not markdown tabs): wrap fences in `:::group` or `:::code-group`. Tab label = `title="file.ts"` or bracket meta `` ```js [abc.js] ``.

| Meta | Effect |
|------|--------|
| `title="file.ts"` | Filename / tab title |
| `frame="terminal"` | Terminal frame |
| `showLineNumbers` / `=false` | Line numbers (on by default for `js,ts,html,java,python`) |
| `startLineNumber=N` | Start numbering at N |
| `{2-3}` or `mark={…}` | Neutral highlight |
| `ins={…}` / `del={…}` | Added / removed lines |
| `ins={"label":4-5}` | Labeled insert/delete |
| `mark="TODO"` | Inline phrase highlight |
| `collapse={1-4,11-13}` | Collapsible ranges |
| `wrap` | Soft-wrap long lines |
| language `diff` | `+` / `-` prefixes |
| language `renderhtml` | **Render** HTML/SVG (add `data-pop-title`/`data-pop` for popovers) |
| language `html` | Highlighted HTML **source** |

## Build and verify

- Diagrams are rendered at **build time** via Kroki (`PUBLIC_KROKI_SERVER_URL`; local: `docker compose -f kroki-local/docker-compose.yaml up -d`). Without a reachable server, builds with diagrams fail or fall back to `https://kroki.io`.
- Run `bun run build` after adding directives, diagrams or new pages. There are no tests.
- Link validation is off by default; enable with `VALIDATE_LINKS=true bun run build` to check internal links.
- Pages are also edited via the `/admin` UI (commits prefixed `[WEB]`); don't rename or move existing pages without need, as URLs and comments (giscus maps by pathname) depend on them.
- Markdown runs through the unified pipeline in `astro.config.mjs` (plugins in `src/lib/`); new syntax requires a plugin there, not just a doc change.

## Nesting rule

Container directives close at the first matching fence of the same length. Outer = more colons:

```md
:::::outer
::::mid
:::inner
…
:::
::::
:::::
```

## Do not

- Uppercase in file or folder names.
- Link to `….md` URLs (they 404).
- Render HTML with an `html` fence or raw HTML.
- Use fewer colons on an outer `:::` than on nested directives.
- Invent asides, diagram fences, or Expressive Code meta this site does not implement.
- Put assets outside `public/` or reference `dist/`.
- Add a leading `# Title` heading duplicating frontmatter `title`.
- Restyle or rewrite unrelated pages.
